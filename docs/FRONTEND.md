## 1. 設計原則

五條。每一條都有理由，違反時必須在 PR 說明為什麼。

### 1.1 這是稽查工具，不是儀表板展示品

使用者是教育局承辦人員，在辦公室桌機上、用 IE 邊緣以外的瀏覽器、一次要看 50–200 筆資料做排程決定。

**含義**：資訊密度優先於留白。表格優先於卡片。預設字級 14px 不是 16px。不要滿版英雄區、不要進場動畫、不要漸層背景。

### 1.2 沒有原因的分數不准出現

任何顯示風險分數的地方，同一個視野內必須能看到「為什麼」。列表頁的每一列、地圖的每一個彈出視窗、詳情頁的分數卡，都要帶 `reasons`。

**理由**：公部門依分數調度稽查人力，被稽查方有權知道理由。這也是評審會問的第一個問題（見 `NARRATIVE.md` §1.1）。

### 1.3 分級只有三色，而且不用綠色

高 / 中 / 低三個等級，色彩是**紅 → 琥珀 → 灰**，沒有綠色。

**兩個理由**：

1. **語意**：低風險不等於「安全」或「合格」。系統只說「這週不優先查」，不說「這家沒問題」。用綠色等於發出一張我們無權發的合格證。灰色的語意是「無優先訊號」，這才是實話。
2. **無障礙**：紅綠是最常見的色覺辨異組合。紅／琥珀／灰在 deuteranopia 與 protanopia 下仍可區分。

**同時不做連續色階**。分數是百分位排名不是絕對量值，連續色階會讓人誤以為 61 分和 59 分有實質差異。

### 1.4 不顯示任何自然人姓名

顯示「同一負責人名下 8 園」，不顯示是誰。後端回傳的就是 `owner_key` 雜湊值，前端**沒有**姓名可顯示，這是設計而非疏漏。

見 [`SPEC.md`](SPEC.md) §10.1。

### 1.5 每個畫面都要能被列印

稽查是紙本流程。派工單是主線產出（§5.7），但列表頁、詳情頁也要有合理的 `@media print` 樣式：去掉導航、展開摺疊區、黑白可讀。

## 2. 設計 Token

全部定義在 `src/styles/tokens.css`，以 CSS custom property 實作。**元件不得寫死色碼**。

### 2.1 色彩

#### 風險分級（語意色，最重要）

| 級別 | 前景 `--c-tier-{x}` | 底色 `--c-tier-{x}-bg` | 邊框 `--c-tier-{x}-border` |
|---|---|---|---|
| 高 | `#B42318` | `#FEF3F2` | `#FECDCA` |
| 中 | `#B54708` | `#FFFAEB` | `#FEDF89` |
| 低 | `#475467` | `#F9FAFB` | `#EAECF0` |

#### 中性色階

```css
--c-text:          #101828;  /* 主文字、表格內容 */
--c-text-2:        #475467;  /* 次要文字、欄位標籤 */
--c-text-3:        #667085;  /* 輔助說明、佔位文字 */
--c-border:        #EAECF0;  /* 表格分隔線、卡片邊框 */
--c-border-strong: #D0D5DD;  /* 輸入框、按鈕邊框 */
--c-bg:            #FFFFFF;  /* 主背景 */
--c-bg-2:          #F9FAFB;  /* 頁面底色、表頭 */
--c-bg-3:          #F2F4F7;  /* hover、選取態 */
```

#### 主色與強調色

```css
--c-primary:       #175CD3;  /* 連結、主要按鈕、選取態 */
--c-primary-hover: #1849A9;
--c-primary-bg:    #EFF8FF;  /* 主色淡底 */
--c-finance:       #DC6803;  /* 財務旗標 💰 */
--c-media:         #6941C6;  /* 輿情訊號 */
--c-danger:        #D92D20;  /* 破壞性操作、錯誤 */
```

#### 資料視覺化

**裁罰類別有 9 種，不要配 9 個顏色。** 9 色類別配色必然有兩色難以區分，而且沒有人記得住對照表。

作法：**類別用文字標籤直接標示，顏色只表達嚴重度**（單色階，5 階）：

```css
--c-sev-1: #EAECF0;   /* 其他行政 */
--c-sev-2: #FEDF89;   /* 收費爭議 */
--c-sev-3: #FDB022;   /* 超收、師生比、師資、交通車 */
--c-sev-4: #F79009;   /* 食安衛生、設施安全 */
--c-sev-5: #B42318;   /* 不當管教、性平事件 */
```

效益曲線四條線（§5.6）：

```css
--c-line-perfect: #D0D5DD;  /* 完美排序，虛線 */
--c-line-model:   #175CD3;  /* 本模型，實線粗 2px */
--c-line-eval:    #6941C6;  /* 只看評鑑 */
--c-line-random:  #98A2B3;  /* 隨機，虛線 */
```

### 2.2 字體

```css
--font-sans: "Noto Sans TC", "PingFang TC", "Microsoft JhengHei",
             -apple-system, "Segoe UI", system-ui, sans-serif;
--font-mono: "SF Mono", "Cascadia Mono", Consolas, monospace;
```

**所有數字一律 `font-variant-numeric: tabular-nums`**，否則表格中的分數與名次會跳動。

| Token | size / line-height / weight | 用途 |
|---|---|---|
| `--t-display` | 28 / 36 / 600 | 詳情頁風險分數大字 |
| `--t-h1` | 22 / 30 / 600 | 頁面標題 |
| `--t-h2` | 18 / 26 / 600 | 區塊標題 |
| `--t-h3` | 16 / 24 / 600 | 卡片標題 |
| `--t-body` | **14 / 22 / 400** | **預設**，表格與內文 |
| `--t-body-strong` | 14 / 22 / 500 | 表格中的園名 |
| `--t-small` | 13 / 20 / 400 | 輔助說明 |
| `--t-caption` | 12 / 18 / 400 | 欄位標籤、圖表軸標 |

### 2.3 間距、圓角、陰影、動效

```css
/* 4px 基準 */
--sp-1: 4px;   --sp-2: 8px;   --sp-3: 12px;  --sp-4: 16px;
--sp-5: 20px;  --sp-6: 24px;  --sp-8: 32px;  --sp-10: 40px; --sp-12: 48px;

--r-sm: 4px;   --r-md: 6px;   --r-lg: 8px;   --r-full: 999px;

--shadow-sm: 0 1px 2px rgba(16,24,40,.05);
--shadow-md: 0 4px 8px -2px rgba(16,24,40,.10);
--shadow-panel: 0 12px 16px -4px rgba(16,24,40,.08);

--ease: cubic-bezier(.4,0,.2,1);
--dur-fast: 120ms;   /* hover、focus */
--dur-base: 200ms;   /* 面板展開、頁籤切換 */
```

**動效規則**：只用於狀態回饋，不用於裝飾。不做進場動畫、不做視差、不做數字跑動。

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    transition-duration: .01ms !important;
  }
}
```

### 2.4 深色模式

**不做。** 使用者是辦公室桌機環境，且派工單以列印為主要輸出。投入產出不成比例，時間應放在派工單與效益曲線上。

## 4. 元件庫

`src/components/`。每個元件列出 props、視覺規格、狀態。

### 4.1 `<TierBadge tier="高" />`

風險分級標籤，全站最常出現的元件。

```
┌──────┐   高：bg --c-tier-高-bg, 字 --c-tier-高, 框 1px --c-tier-高-border
│  高  │   中：同上換 token
└──────┘   低：同上換 token
```

| 屬性 | 值 |
|---|---|
| 尺寸 | `padding: 2px 8px`，`--t-caption`，`font-weight: 500` |
| 圓角 | `--r-full` |
| 變體 | `size="sm"`（表格內）/ `size="md"`（詳情頁） |

**無障礙**：色彩不是唯一訊息載體，標籤內有「高/中/低」文字。

### 4.2 `<RiskScore score={87.4} rank={23} tier="高" />`

詳情頁的分數卡。

```
┌──────────────────────────────────────────┐
│ 風險總分                    資料涵蓋 83%  │
│                                           │
│  87.4         全市第 23 名 / 1,178 ┌────┐│  ← --t-display
│  ▔▔▔▔▔▔▔▔                        │ 高 ││
│  私立同儕群中前 12.6%              └────┘│  ← --t-small --c-text-2
│ ─────────────────────────────────────────│
│ 違規  96.8  ×50.0%   ████████████▏       │
│ 評鑑  74.1  ×28.6%   █████████▎          │
│ 輿情  31.2  ×21.4%   ███▉      涵蓋 40%  │
│ 營運    ——           私立依法不需公告財報 │
└──────────────────────────────────────────┘
```

分數下方 `▔▔▔` 是 4px 進度條，寬度 = `score%`，色彩用 tier 前景色。

| 規則 | 說明 |
|---|---|
| **必須顯示四維度拆解** | 否則使用者無法理解 87.4 從哪來 |
| 權重從 `GET /meta` 讀 | 依 `institution_type` 取對應權重，**不寫死** |
| `applicable = false` | 顯示 `——` 與 `note` 文字，**絕不顯示 0** |
| `coverage < 0.8` | 該維度旁標「涵蓋 X%」，提醒分數建立在部分資料上 |
| `validated = false` | 維度名稱旁加 ⓘ，hover 顯示「此維度依財務常規判斷，尚無足夠裁罰樣本可驗證」 |
| 分數語意 | 主分數下方必須寫「{類型}同類中前 X%」，不可只寫數字 |

**營運維度的特別處理**：`validated = false` 是永久狀態，不是待補。前端不得把它畫成「載入中」或「資料不足」——它是一個有意識的設計選擇，文案要說清楚。

### 4.3 `<ReasonList reasons={[...]} max={3} />`

白話原因清單。**全站最重要的元件**（原則 1.2）。

```
▸ 切點前已被裁罰 5 次，同類型前 3%                       [違規]
▸ 基礎評鑑 2 次未全數通過，並曾受幼照法第 51 條行政處分    [評鑑]
▸ 所在行政區近 90 天輿情熱度全市第 4                      [輿情]
```

營運維度的原因會多一個 ⓘ（見下方 `validated` 規則）：

```
▸ 人事費執行率 64%，同儕中位數 90%                    ⓘ [營運]
```

| 屬性 | 規格 |
|---|---|
| `reasons` | `[{code, label, weight, dimension, validated}]`，來自 API |
| 排序 | 依 `weight` 由大至小，**後端已排好，前端不再排序** |
| 上限 | 固定 3 條。超過 3 條沒有人會讀完 |
| `dimension` 標記 | 違規 `--c-tier-高` / 評鑑 `--c-primary` / 輿情 `--c-media` / 營運 `--c-finance`，12px 標籤 |
| `validated: false` | 標籤前加 ⓘ，hover 顯示「此維度依財務常規判斷，尚無足夠裁罰樣本可驗證」。**僅營運維度會出現** |
| 同維度上限 | 後端已限制同一維度最多 2 條，前端不再過濾 |
| 文案 | **直接顯示 `label`，前端不做字串拼接**。所有白話文由後端產生 |

**為什麼文案不在前端組**：原因文字需要跟模型係數一致，而且要能被 LLM 潤飾後覆寫。前端拼接會讓兩邊不同步。

### 4.3b `<CoverageBar coverage={0.83} />`

資料涵蓋率指示。v2 的分數是覆蓋率加權的（[`SPEC.md`](SPEC.md) §5.1），使用者必須看得到這個分數建立在多少資料上。

```
資料涵蓋 83%   ████████▎░░
```

| coverage | 顏色 | 文案 |
|---|---|---|
| ≥ 0.8 | `--c-text-2` | 「資料涵蓋 83%」 |
| 0.5–0.8 | `--c-finance` | 「資料涵蓋 62%，部分維度缺資料」 |
| < 0.5 | `--c-tier-中` | 「資料涵蓋 34%，此分數參考性有限」 |

**低覆蓋率不等於低風險，也不等於高風險。** 文案只陳述事實，不做方向暗示。

### 4.4 `<DataTable />`

列表頁主體。1,178 筆資料，**分頁而非虛擬捲動**（每頁 50 筆），理由是使用者需要「第幾頁」這個可溝通的位置感。

| 規格 | 值 |
|---|---|
| 列高 | 48px（含 `reasons` 時 72px） |
| 表頭 | `position: sticky; top: 0`，底色 `--c-bg-2`，`--t-caption`，`--c-text-2` |
| 分隔線 | `border-bottom: 1px solid --c-border` |
| hover | 整列 `--c-bg-3` |
| 可排序欄 | 表頭顯示 ▲▼，點擊切換，狀態寫進 URL `?sort=risk&dir=desc` |
| 數字欄 | 靠右對齊 + `tabular-nums` |
| 園名欄 | `--t-body-strong`，連結至 `/park/:id` |
| 空狀態 | 見 §6.2 |

**欄位順序**（固定，不可自訂 — 自訂欄位是 v2 的事）：

```
名次 │ 園名 │ 行政區 │ 設立別 │ 風險分 │ 分級 │ 裁罰次數 │ 旗標 │ 上榜原因
 56  │ 320  │  80    │   72   │   72   │  56  │    72    │  64  │  剩餘
```

### 4.5 `<FilterBar />`

```
┌──────────────────────────────────────────────────────────────────┐
│ [🔍 搜尋園名                    ]  行政區 ▾  設立別 ▾  分級 ▾     │
│                                                                   │
│ 已選：板橋區 ✕  三重區 ✕  私立 ✕  高 ✕            清除全部       │
│                                    共 47 筆 · 佔母體 4.0%         │
└──────────────────────────────────────────────────────────────────┘
```

| 行為 | 規格 |
|---|---|
| 搜尋 | debounce 300ms，最少 1 字觸發 |
| 多選 | 下拉為 checkbox 清單，可搜尋（行政區有 29 個） |
| 已選 chip | 可個別移除，`--c-primary-bg` 底 |
| **狀態同步 URL** | `?town=板橋區&town=三重區&type=私立&tier=高` |
| 結果計數 | 即時顯示「共 N 筆 · 佔母體 X%」 |

**URL 即狀態**：所有篩選、排序、分頁都寫進 query string。使用者可以把連結貼給同事、可以按上一頁、重新整理不會遺失。這對公部門協作是必要的，不是加分項。

### 4.6 `<PunishmentTimeline items={[...]} />`

裁罰時間軸，詳情頁核心元件。

```
2025 ─────────────────────────────────────────────  切點後
      │
      ● 2025-03-14  不當管教  罰鍰 60,000 元        ← sev-5 紅點
      │  第33條第1項 教保服務人員對幼兒不當對待
      │
━━━━━━━━━━━ 切點 2025-01-01 ━━━━━━━━━━━━━━━━━━━━  ← 虛線 + 標籤
      │
2024  ● 2024-03-26  師生比    罰鍰 6,000 元         ← sev-3 橘點
      │  第16條第4項
      │
2023  ● 2023-07-03  超收      罰鍰 60,000 元
      ● 2023-07-03  師生比    罰鍰 6,000 元
      │
2020  ● 2020-09-23  超收      罰鍰 6,000 元
```

| 規格 | 值 |
|---|---|
| 圓點色 | 依 `category` 對應的 severity（`--c-sev-1..5`） |
| **切點分隔線** | 必須明確畫出，標註「切點 2025-01-01」 |
| 切點後項目 | 底色 `--c-bg-2`，右上角標「標籤期間」 |
| `fine` 為 null | 顯示處分原文（「停止招生」等），**不顯示 0 元** |
| 排序 | 新到舊 |
| 摺疊 | 超過 8 筆時摺疊，顯示「展開其餘 N 筆」 |

> **切點分隔線是本系統可信度的視覺化。** 它讓使用者一眼看到「線以上的資料模型沒看過」。Demo 時這個畫面要停留 5 秒。

### 4.7 `<FinanceFlag flags={[...]} />`

```
💰 財務旗標 2 項
   ├ 人事費執行率 64%，46 份中第 3 低                〔112 學年度〕
   └ 代課代班費執行率 30%                            〔113 學年度〕
```

## 6. 狀態設計

四種狀態，每個資料區塊都要實作。**不做只寫 happy path 的元件**。

### 6.1 載入中

用骨架屏，不用 spinner。骨架形狀要接近實際內容。

```
▬▬▬▬▬▬▬▬▬▬▬▬▬▬  ▬▬▬▬▬  ▬▬▬  ▬▬▬▬
▬▬▬▬▬▬▬▬▬▬▬     ▬▬▬▬▬  ▬▬▬  ▬▬▬▬
```

`background: linear-gradient` 淡掃動畫，1.5s 循環，`prefers-reduced-motion` 時改為靜態 `--c-bg-3`。

### 6.2 空結果

```
        沒有符合條件的園所

   目前條件：板橋區 + 非營利 + 高風險
   新北市非營利幼兒園共 53 家，其中板橋區 2 家

        [ 清除分級篩選 ]  [ 清除全部 ]
```

**空狀態必須說明為什麼空，並提供下一步。** 只寫「查無資料」是不合格的。

### 6.3 錯誤

```
        資料載入失敗

   無法取得風險列表（HTTP 503）
   這通常是暫時性問題

        [ 重試 ]        錯誤代碼 REQ-8f3a2
```

| 規格 | 值 |
|---|---|
| 重試 | 前端自動重試 1 次（間隔 1s），失敗後才顯示此畫面 |
| 錯誤代碼 | 顯示 `x-request-id`，方便對 CloudWatch Logs |
| 不要 | 不要顯示 stack trace、不要顯示 AWS 資源名稱 |

### 6.4 部分資料缺失

不是錯誤，是常態。**每一種缺失都要有明確文案**：

| 情境 | 文案 |
|---|---|
| 私幼無財報 | 「私立幼兒園依法不需公告財務報告」 |
| 私幼／非營利無收費明細 | 「收費明細僅公立幼兒園公告，本園無此資料」 |
| 公立附設園無財務 | 「本園為附設幼兒園，財務併入所屬學校，營運分數僅依收費明細計算」 |
| 非營利無財報 | 「查無本園財務報告，營運維度不適用」 |
| 無輿情訊號 | 「未偵測到明文點名之報導。未被報導不代表無風險」 |
| 無評鑑紀錄 | 「查無切點前之評鑑紀錄，可能為新立案園所」 |
| 座標缺失 | 地圖上不顯示，列表正常顯示，詳情頁標「無座標資料」 |

## 7. 無障礙

目標 **WCAG 2.1 AA**。政府專案這是基本要求，不是加分項。

| 項目 | 要求 | 驗證方式 |
|---|---|---|
| 對比度 | 內文 ≥ 4.5:1，大字 ≥ 3:1 | 已設計的 token 全數通過，變更色彩時須重驗 |
| 色彩非唯一載體 | tier 標籤有文字、圖表有直接標籤、時間軸有類別文字 | 灰階列印後仍可讀 |
| 鍵盤操作 | 所有互動元素可 Tab 抵達，focus ring 2px `--c-primary` | 全站不用滑鼠走一遍 |
| 語意標籤 | 表格用 `<table>` 不用 div、表頭 `<th scope>`、地標 `<nav>/<main>` | axe DevTools 零 critical |
| 動態內容 | 篩選結果變更以 `aria-live="polite"` 播報筆數 | 螢幕閱讀器測試 |
| 圖表 | 提供 `<table>` 形式的替代資料（可摺疊） | 效益曲線下方已有對照表 |
| 縮放 | 200% 縮放不破版 | 手動 |

## 9. 技術規格

### 9.1 技術選型

| 項目 | 選擇 | 理由 |
|---|---|---|
| 框架 | React 18 + TypeScript | 團隊熟悉度 |
| 建置 | Vite | 快、設定少 |
| 路由 | React Router v6 | |
| 狀態 | **URL query string + TanStack Query** | 不需要 Redux。伺服器狀態交給 Query，UI 狀態放 URL |
| 樣式 | CSS Modules + design token | 不引入 UI 框架，避免為了覆寫樣式而打架 |
| 圖表 | 自繪 SVG（效益曲線只有 4 條線） | 不為一張圖引入 200KB 圖表庫 |
| 地圖 | MapLibre GL JS | 開源、支援 canvas 渲染大量點位 |
| 表格 | 自建 | 需求單純，不需 TanStack Table |
| 測試 | Vitest + Testing Library | |

**不引入 UI 框架**（MUI / Ant Design）：政府風格的密集表格與這些框架的預設風格差距大，覆寫成本高於自建。元件總數約 20 個，可控。

### 9.2 目錄結構

### 9.3 API client 規範

```ts
// 所有請求統一經過 client
const BASE = import.meta.env.VITE_API_BASE ?? '/api/v1';

// 必要行為
// 1. 逾時 10s
// 2. 5xx 自動重試 1 次，間隔 1s
// 3. 記錄回應的 x-request-id，錯誤畫面顯示
// 4. 4xx 不重試，直接進錯誤狀態
// 5. 回應以 zod schema 驗證，不符合視為錯誤
```

**回應要做 schema 驗證**：後端契約若改欄位，前端要立刻在開發期爆錯，而不是畫面默默空白。

### 9.4 Mock 資料

`mock/` 下放與 [`SPEC.md`](SPEC.md) §8 同 schema 的假資料：

```
mock/
├── meta.json
├── parks.json          200 筆，涵蓋三種 tier、三種設立別
├── park-detail.json    3 筆（高風險有旗標 / 中風險無旗標 / 停辦園）
├── risk-top.json
├── districts.json      29 區
├── map.json
├── curve.json
└── worklist.json
```

`VITE_API_BASE=mock` 時 client 改讀本地檔案。**前端 D0 即可全速開發，不等後端與模型。**

Mock 資料必須包含這些邊界案例，否則狀態設計會被漏掉：

- 無座標的園（地圖不顯示）
- 無財報的私幼（頁籤置灰）
- 無輿情訊號的園（`sri=0, has_signal=false`）
- 無評鑑紀錄的新園
- 裁罰超過 8 筆需摺疊的園
- 已停辦園
- 園名超長需截斷的園（最長全名 40 字以上）

## 附錄 A — 文案原則

UI 文案由前端負責，**但風險原因與查核建議一律由後端產生**（§4.3）。

| 原則 | 錯 | 對 |
|---|---|---|
| 說事實不說結論 | 「這家園很危險」 | 「切點前已被裁罰 5 次，同類型前 3%」 |
| 給數字不給形容詞 | 「裁罰紀錄偏多」 | 「裁罰 5 次，同類型前 3%」 |
| 缺資料說原因 | 「無資料」 | 「私立幼兒園依法不需公告財務報告」 |
| 不暗示合格 | 「低風險 ✓ 安全」 | 「低風險 — 本週不列入優先稽查」 |
| 不指認個人 | 「負責人王○○」 | 「同一負責人名下另有 7 園」 |
| 承認不確定 | 「財務異常」 | 「財務旗標，不計入風險分數，僅供人工複查」 |
