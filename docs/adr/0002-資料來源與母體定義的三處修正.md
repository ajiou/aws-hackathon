# ADR-0002：資料來源與母體定義的三處修正

| | |
|---|---|
| 日期 | 2026-09-12 |
| 狀態 | 已採納，待團隊確認 |
| 影響 | `SPEC.md` §1.1 母體、§2.1 資料盤點、§14.1 驗收 |

## 背景

ASSIGNMENTS 的共同規則要求「數字要實測，不要沿用文件裡的舊數字」。
A 軌實作時逐項對過，有三處與規格不符，全部已在程式內處理並加 assert。

## 一、裁罰單一事實來源：`punish.json` 就是 `watchdog.db.punishments`

**規格說**：裁罰紀錄的單一事實來源是 `sentinel/data/watchdog.db` 的
`punishments` 表（§2.1 第 2 列）。

**實測**：該 db 不在 repo 也不在本機。但 `data/punish.json` 是它的等價匯出——
7,007 筆紀錄的 `id` 欄與 `preschools.json` 的 park_id **7,007 / 7,007 完全對得上**。
新北 1,464 筆 / 486 園，其中切點後 248 筆 / **128 園，正好等於標籤正樣本數**。

**決定**：ETL 直接讀 `punish.json`。它的 key 是 `"負責人：姓名"` /
`"行為人：姓名"`，姓名在 key 上，拆出來雜湊成 `target_key`，角色存 `target_role`。

**連帶**：新北裁罰是 **1,464 筆**，不是 §2.1 寫的 1,423——`punish.json`
抓到 2026-08-21，比規格寫作時新。

## 二、`features.json` 是 1,215 筆，不是 1,212

**規格說**：§14.1 的驗收項目是「`features.json` 1,212 筆」。

**實測**：1,212 是 `園所裁罰特徵.json` 的涵蓋數，比新北母體少 3 園。
那 3 園是——

| 園名 | 設立別 | is_active |
|---|---|---|
| 新北市碧城非營利幼兒園 | 非營利 | **1** |
| 新北市安興非營利幼兒園（委託社團法人臺灣兒童教育發展協會辦理） | 非營利 | **1** |
| 新北市北大非營利幼兒園（委託社團法人中華音樂舞蹈暨表演藝術教育協會辦理） | 非營利 | **1** |

三家都在營運中，其中**安興與北大正是 B 軌僅有的 12 家財報園中的 2 家**，
安興更是 `NARRATIVE.md` §4.4 的主敘事案例（112 學年度人事費執行率 64%、
同學年被裁罰 3 次不當管教）。

**決定**：照 §1.1 原文「缺 3 園，ETL 需以 left join 補 0」，`features.json`
產出 **1,215 筆**。為了讓一個 checkbox 過關而砍掉主敘事的案例不划算。

**正樣本仍為 128**——1,212 與 1,215 兩種母體實測皆同，且與特徵檔的
`標籤_切點後被罰` 欄逐筆相符。

## 三、母體組成：私立 835 / 公立 290 / 非營利 53

**規格說**：§5.0 與 §6.4 寫私立 868 園、公立 294 園。

**實測**：那是**含已停辦園**的數字。本系統母體是 `is_active == 1` 的 1,178 園，
組成為 **私立 835 / 公立 290 / 非營利 53**。

**決定**：排名、分級、效益曲線、同儕群一律用 1,178 的組成。
`features.json` 保留全部 1,215 筆並帶 `is_active`，供 API 查詢停辦園使用。

## 附帶修正：`處分次數` 算的是日期，不是法條筆數

這不是規格錯，是實作時差點弄錯的定義，記在這裡避免下一個人重踩。

同一次稽查常同時開出多條法規——嘉府 2024-05-31 一天就開出超收、師生比、
進用未具資格三條。按法條筆數算會把「一次稽查」放大成「三次違規」。

以 distinct date 聚合後，與 `園所裁罰特徵.json` 的 `園_處分次數`
**1,212 / 1,212 完全相符**——那份檔就是這樣算的。

嚴重度取當日各法條的**最大值**，不是加總；加總會讓「一次稽查開三條輕罪」
看起來比「一次不當對待」嚴重。
